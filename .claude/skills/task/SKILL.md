Задача: $ARGUMENTS

Ты оркестратор. Правила: `AGENTS.md`; роли, классы действий и доказательства:
`docs/planning/13-harness.md` (дальше §N); бэклог и решения: спека блока по ссылке из
`docs/NEXT_SESSION.md`. Этот skill задаёт только порядок; при расхождении главнее регламент.

1. Карточка. Аргумент вида `W<n>-T<nn>`: прочитай карточку в спеке («Вход», «Файлы», «Готово,
   когда», «Зависит от») и статусы её решений. Иначе это фраза: разверни её в мини-карточку того же
   вида (цель, границы, что не трогаем, «Готово, когда», риски, класс действий по §2). Вопросы
   владельцу: не больше трёх и только те, без ответа на которые нельзя продолжать.
2. Вход. Места и цитаты: `Explore`. Анализ, сверка документа с кодом, версии, живые пробы: `scout`.
   Брифы по шаблону §3. Ответ в 1-3 известных файлах читай сам.
3. План: шаги по файлам, кто пишет каждый (`implementer` или сам по порогу §1), проверки, класс
   действия каждого шага, что требует «ок». Стоп и жди «ок» владельца, если спека не делегировала
   это решение.
4. Реализация: `implementer` по брифу, первым тест на отказ; параллельно только разные файлы. Сам:
   правка до ~20 строк в одном файле, Markdown, шаги на живом стеке.
5. Приёмка отчёта исполнителя (§3): ключевую проверку перезапусти сам, сверь `git diff --stat` с
   «Границами», открой 2 ссылки `file:line`.
6. Проверки: `make check`; затронутые `make test-spark`, `make dags-check`, `make alerts-test`,
   `make dbt-parse`.
7. Ревью (§4): `reviewer` получает diff, «Готово, когда», выполненные проверки с выводом и предмет
   «код», без твоих рассуждений. Замечания: разбери каждое, исправления брифом `implementer`, `make check`, тот же
   `reviewer` по изменённым строкам. Не больше двух кругов, дальше стоп и вопрос владельцу (§7).
8. Verify и коммит (§5): цикл verify, одна карточка один коммит; «ок» на diff, если спека не
   делегировала коммит. Гейт `guard.py` пустит коммит кода только с отметкой `make check` и
   вердиктом `reviewer` по этому дереву.
9. Итог (§6) в карточку и HANDOFF; владельцу: что сделано, команды с выводом, что не проверено,
   что ждёт его решения, `git status --short`, `git diff --stat`.
