Задача: $ARGUMENTS

Ты оркестратор. Правила: `AGENTS.md`; роли, классы действий и доказательства:
`docs/planning/13-harness.md` (дальше §N); бэклог: `docs/planning/21-final-audit-2026-11-13/README.md`,
раздел 4. Этот skill задаёт только порядок; при расхождении главнее регламент.

0. Рутина сессии (`AGENTS.md`, «Цикл»): если в журнале «ок» `docs/HANDOFF.md` нет записи за
   сегодня и аргумент её не даёт, первым сообщением один вопрос владельцу: рутина сессии,
   решения В-n пакета, точные тексты действий класса C.
1. Карточка. Путь к файлу пакета (`P<nn>-*.md`): прочитай его целиком («Решения», «Зависимости»,
   «Вход», «Границы», «Шаги», «Готово, когда») и разделы 3-5 README его папки. ID `W<n>-T<nn>`:
   карточка в спеке. Иначе это фраза: разверни её в мини-карточку того же вида (цель, границы,
   что не трогаем, «Готово, когда», риски, класс действий по §2). Вопросы владельцу: не больше
   трёх и только те, без ответа на которые нельзя продолжать.
2. Вход. Места и цитаты: `Explore`. Анализ, сверка документа с кодом, версии, живые пробы: `scout`.
   Брифы по шаблону §3. Ответ в 1-3 известных файлах читай сам. Факт не подтвердился: шаг не
   исполнять, записать в «Итог».
3. План: шаги по файлам, кто пишет каждый (`implementer` или сам по порогу §1), проверки, класс
   действия каждого шага, что требует «ок». Вне рутины сессии стоп и жди «ок» владельца.
4. Реализация: `implementer` по брифу, первым тест на отказ; параллельно только разные файлы. Сам:
   правка до ~20 строк в одном файле, Markdown, шаги на живом стеке.
5. Приёмка отчёта исполнителя (§3): ключевую проверку перезапусти сам, сверь `git diff --stat` с
   «Границами», открой 2 ссылки `file:line`.
6. Проверки: `make check`; затронутые `make test-spark`, `make dags-check`, `make alerts-test`,
   `make dbt-parse`.
7. Ревью (§4): `reviewer` получает diff, «Готово, когда», выполненные проверки с выводом и предмет
   «код», без твоих рассуждений. Замечания: разбери каждое, исправления брифом `implementer`,
   `make check`, тот же `reviewer` по изменённым строкам. Не больше двух кругов, дальше стоп и
   вопрос владельцу (§7).
8. Verify и коммит (§5): цикл verify, если его требует гейт; один пакет один коммит; «ок» на diff
   вне рутины сессии. Гейт `guard.py` пустит коммит кода только с отметками его уровня.
9. Итог (§6) в файл пакета, его статус и таблицу раздела 4 README папки, верх HANDOFF; владельцу:
   что сделано, команды с выводом, что не проверено, что ждёт его решения, `git status --short`,
   `git diff --stat`.
