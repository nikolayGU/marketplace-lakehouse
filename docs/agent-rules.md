# Правила кода

Версия 2.0, 19.11.2026. Только правила кода и инфраструктуры для любого агента. Обязательное
(чтение, цикл, запреты, коммиты, язык, секреты) в `AGENTS.md`, он главнее; как исполнять, в
`docs/planning/13-harness.md`. Прежние версии: `git log -p docs/agent-rules.md`.

## Принципы

- Маленькие изменения: одна задача, один diff, один коммит. Соседний код «заодно» не рефакторить.
- Контракты (`contracts/`, схемы silver, имена топиков и таблиц, переменные `.env`) не менять без
  причины и записи в `DECISIONS.md`.
- Работающий и покрытый тестом код не переписывать; некрасивое предложить владельцу отдельно.
- KISS и YAGNI: ни абстракций, ни сервисов «на будущее». Новый сервис только через ADR.
- Архитектуру решает владелец: агент приносит варианты с trade-offs и ждёт выбора.
- Версии, флаги, поведение инструментов сверять с документацией нужной версии или запуском.

## После каждого изменения

- Проверки: `make check` для Python; `make dbt-parse` и `dbt build --select <model>` для dbt;
  `docker compose config -q` для compose; `sqlfluff lint` для SQL.
- Compose, Dockerfile, SQL, конфиги: показать ручную проверку (команда и ожидаемый вывод).
- Влияние на пайплайн: checkpoint, таблицы Iceberg, offsets, DAG. Если ответ «удалить checkpoint
  или таблицу», написать это явно и ждать «ок».
- Изменилось поведение: обновить `OPERATIONS.md`, `DECISIONS.md`, docstring контракта.

## Код

- Python 3.12, `uv`, `ruff` (lint и format), типы везде (`mypy`), `pytest`. Конфиг только через
  env (`pydantic-settings`), без хардкода хостов и портов.
- Комментарий только там, где имя не объясняет поведение (ключ dedup, условие MERGE, watermark).
  Docstring короткий, на публичных функциях с неочевидной семантикой.
- SQL: `sqlfluff`, ключевые слова строчными, CTE вместо вложенных подзапросов, в dbt только
  `{{ ref() }}` и `{{ source() }}`.
- Spark: PySpark, `local[2]`, явные схемы из `contracts/`, никаких `inferSchema`.
- Тесты в одном коммите с кодом. Тест проверяет поведение, включая отказы (дубли, late,
  невалидный JSON).

## Compose и инфраструктура

Каждый долгоживущий сервис в `docker/compose.yaml`: `profiles`, `healthcheck` с реальной
проверкой, `restart: unless-stopped`, `logging: *logging`, `deploy.resources.limits.memory`, для
JVM явный `-Xmx` через env, `depends_on` с `condition: service_healthy`. Порты только на
`${BIND_IP:?...}` (`127.0.0.1`), ни одного порта на `0.0.0.0`. Разовые задачи: `restart: "no"`,
без healthcheck. Исключения в `ARCHITECTURE.md`, «Resource model». Образы закреплены тегом, не
`latest`. В коде, compose и workflows только `${VAR}`.

## Гейты понимания

Владелец закрывает этапы гейтами Read, Explain, Operate, Modify
(`docs/planning/02-learning-gates.md`). Modify-гейт агент за владельца не делает: называет файл и
функцию, даёт подсказку или тест, но не готовый код. На «объясни» объясняет полностью, с
trade-offs, и задаёт 2-3 встречных вопроса.

## Когда не уверен

- Проверить документацию или запустить и посмотреть вывод.
- Проверить нельзя: «не уверен, предлагаю эксперимент: <команда, что ожидаем>», и стоп.
- Решение меняет архитектуру: стоп, варианты, выбор владельца.
