## 8. Сессия

1. Старт, только чтение: `make report`, `docker ps`, `gh run list --limit 5`, `make verify-fast`,
   `curl -s 127.0.0.1:9090/api/v1/alerts`, `make replay-status`. Расхождение с HANDOFF записать.
2. Одним сообщением владельцу: решения группы C без статуса «принято» (вопрос, рекомендуемый ответ,
   цена отказа), нужные «ок», обновлённая таблица «Действия владельца» в HANDOFF.
3. Работа по разделу 5 спеки: первая строка с выполненными зависимостями и принятыми решениями.
   Пока решений нет, только работа из строки «без решений» раздела 5 спеки; кончилась: стоп.
4. Цикл карточки (`/task <ID>`): «Вход» (`Explore`, `scout`) → короткий план в отчёт → тест на
   отказ и правка (`implementer`) → `make check` → ревью → исправления (`implementer`, не больше
   двух кругов) → verify → коммит → «Итог» карточки и HANDOFF.
5. Конец: раздел HANDOFF «Состояние на <дата>», `docs/NEXT_SESSION.md`, журнал «ок»,
   `git status --short`, `git diff --stat`, список того, что ждёт владельца.

## 9. Признаки, что регламент работает

- `tests/unit/test_agent_hooks.py` зелёный; каждая строка класса C из раздела 2, видимая по тексту,
  есть в `test_guard_asks_the_owner` или `test_guard_denies`.
- Холодный старт: новая сессия только по `NEXT_SESSION.md` за первые 15 минут выдаёт верные HEAD,
  статус smoke и CI, список решений владельца и следующую работу.
- У каждого коммита с кодом есть отчёт `reviewer` (с v0.3 без вердикта по дереву коммита гейт не
  пускает); у каждой закрытой карточки запись по разделу 6.
- В журнале «ок» есть строка на каждое действие C, видимое в git, HANDOFF и OPERATIONS.

## 11. Доказательства процесса

Проект показывает и продукт, и то, как его строили агенты. Метрик эффективности не придумывать;
всё считается из артефактов, которые и так ведутся:
- решения: `DECISIONS.md` и раздел 2 спеки (группа, кто решил, ссылка на ревью);
- делегирование и ревью: «Итог» каждой карточки называет исполнителя (оркестратор или роль) и
  вердикт `reviewer`;
- участие владельца: строки журнала «ок» и таблицы «Действия владельца» в HANDOFF против числа
  коммитов блока (`git log --oneline 8964292..HEAD | wc -l`);
- проверки: CI и smoke run по ссылкам, числа живых прогонов с датой.
При «W6-D15: да» W6-T02 собирает это в раздел «How it was built» в `docs/evidence.md`.

Сессию исполнителя запускать в режиме `default` или `acceptEdits`. Не запускать с `--bare` (хуки не
работают) и с `bypassPermissions`.
